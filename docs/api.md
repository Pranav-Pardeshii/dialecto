# API contract

Base path: `/api/v1`. JSON everywhere (UTF-8). This document is the contract for both apps: the backend implements it slice by slice (see `plan.md`) and the frontend generates its types from the exported `openapi.json`.

## Conventions

- **Demo identity:** header `X-Demo-User-Id: <int>` selects a seeded user. Missing or unknown id returns `401 unknown_user`. Teacher routes require `role = teacher`, otherwise `403 forbidden`.
- **Request tracing:** the server returns `X-Request-Id` on every response.
- **Idempotency:** answer submissions carry `client_attempt_id` (UUID v4 generated by the client). A duplicate returns the original response with `200`.
- **IDs:** content ids are slugs (strings); runtime ids are integers.
- **Timestamps:** ISO 8601 UTC.
- **Error envelope (all non-2xx):**

```json
{
  "error": {
    "code": "ai_unavailable",
    "message": "The tutor is busy right now. Please try again in a moment.",
    "details": {},
    "request_id": "01J..."
  }
}
```

Common codes: `validation_error` (422), `unknown_user` (401), `forbidden` (403), `not_found` (404), `turn_in_progress` (409), `session_closed` (409), `rate_limited` (429, with `Retry-After`), `ai_unavailable` (503), `internal_error` (500).

## Endpoints

### Health and ops

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | liveness (no dependencies). Not under `/api/v1` |
| GET | `/ready` | readiness: DB reachable, config sane. Not under `/api/v1` |
| GET | `/api/v1/ops/llm-stats` | last-hour LLM reliability stats (calls per model, fallback rate, p50 and p95 latency, error counts, breaker states) |

### Identity

| Method | Path | Purpose |
|---|---|---|
| GET | `/users` | demo identities for the role switcher: `[{id, display_name, role, is_simulated}]` (excludes simulated by default; `?include_simulated=true`) |
| GET | `/me` | current user |

### Content

| Method | Path | Purpose |
|---|---|---|
| GET | `/concepts` | graph: `{nodes: [{id, name, chapter, position}], edges: [{from, to}]}`; for students each node also has `mastery: {p_effective, status}` |
| GET | `/concepts/{concept_id}` | detail: `{id, name, chapter, description, lesson_md, prerequisites[], misconception_count}`. **Never includes `key_points`** |

### Learner

| Method | Path | Purpose |
|---|---|---|
| GET | `/learner/mastery` | `[{concept_id, p_mastery, p_effective, attempts, last_seen_at, next_due_at, status}]` |
| GET | `/learner/summary` | `{overall_mastery, weakest: [concept_id], due_count, active_misconceptions: [{id, statement, concept_id}]}` |

`status` is one of `locked`, `unlocked`, `learning`, `mastered`.

### Diagnostic

| Method | Path | Purpose |
|---|---|---|
| POST | `/diagnostic/sessions` | start; returns `{session_id, question, progress: {answered, total}}` |
| POST | `/diagnostic/sessions/{id}/answers` | submit; returns `{is_correct, next_question \| null, progress, result \| null}` |
| GET | `/diagnostic/sessions/{id}/result` | `{mastery: [...], weakest: [...], recommended_next: concept_id}` |

Answer body: `{client_attempt_id, question_id, selected_key, reasoning?: string}`.

### Practice

| Method | Path | Purpose |
|---|---|---|
| POST | `/practice/next` | body `{mode: "adaptive" \| "review" \| "concept", concept_id?}` returns `{session_id, question, selection_reason}` |
| POST | `/practice/answers` | submit an answer (see example) |

Question object (never contains the correct key or distractor tags):

```json
{
  "id": "q-lp-photosynthesis-03",
  "concept_id": "lp-photosynthesis",
  "stem": "During photosynthesis, the oxygen released comes from which molecule?",
  "options": [
    {"key": "A", "text": "Carbon dioxide"},
    {"key": "B", "text": "Water"},
    {"key": "C", "text": "Glucose"},
    {"key": "D", "text": "Chlorophyll"}
  ],
  "difficulty_bucket": 2
}
```

`POST /practice/answers` request:

```json
{
  "client_attempt_id": "0b0f6f4e-6b79-4c1c-8f0a-9d4f4f2b6b11",
  "session_id": 42,
  "question_id": "q-lp-photosynthesis-03",
  "selected_key": "A",
  "reasoning": "CO2 is the gas that goes in so I think the oxygen is from it",
  "response_ms": 14200
}
```

Response:

```json
{
  "is_correct": false,
  "correct_key": "B",
  "explanation": "The oxygen comes from the splitting of water molecules.",
  "mastery": {"concept_id": "lp-photosynthesis", "before": 0.41, "after": 0.27, "status": "learning"},
  "next_due_at": "2026-11-01T09:00:00Z",
  "misconception": {
    "id": "m-o2-from-co2",
    "statement": "The oxygen released comes from carbon dioxide",
    "correction": "Light energy splits water; the oxygen is released from water.",
    "source": "llm_reasoning",
    "confidence": 0.86
  },
  "ai": {"used": true, "model": "openai/gpt-oss-120b", "fallback": false},
  "newly_unlocked": []
}
```

`misconception` is `null` when none was detected. `ai.used` is `false` when only the deterministic distractor tag was available.

### Teach-Back

| Method | Path | Purpose |
|---|---|---|
| POST | `/teachback/sessions` | body `{concept_id}` returns the session plus Pip's opening line |
| POST | `/teachback/sessions/{id}/turns` | body `{content}` (max 2,000 chars) returns Pip's reply and feedback |
| GET | `/teachback/sessions/{id}` | full transcript and state |

Turn response:

```json
{
  "turn_index": 3,
  "pip": {"content": "Ohh, so the plant breaks water apart? But where does the CO2 go then?", "level": 1},
  "feedback": {
    "score": 0.52,
    "covered": ["Needs light, chlorophyll, CO2 and water"],
    "missing": ["Oxygen comes from splitting of water"],
    "misconceptions": [{"id": "m-o2-from-co2", "statement": "The oxygen released comes from carbon dioxide"}]
  },
  "finished": false,
  "result": null,
  "ai": {"model": "openai/gpt-oss-120b", "fallback": false}
}
```

When `finished` is true, `result` is `{final_score, final_level, mastery: {before, after}, strengths[], gaps[]}`. A session finishes when Pip reaches level 3 or after 4 learner turns. A further turn returns `409 session_closed`.

### Speech (fallback mic)

| Method | Path | Purpose |
|---|---|---|
| POST | `/speech/transcriptions` | multipart `audio` (max 5 MB) returns `{text}` |

### Reviews

| Method | Path | Purpose |
|---|---|---|
| GET | `/reviews/due` | `[{concept_id, name, p_effective, days_overdue}]` ordered by priority. Review questions are fetched via `/practice/next` with `mode: "review"` |

### Teacher (role = teacher)

| Method | Path | Purpose |
|---|---|---|
| GET | `/teacher/classrooms/{id}/heatmap` | `{concepts: [{id, name}], students: [{id, display_name}], cells: [{student_id, concept_id, p_effective}]}` |
| GET | `/teacher/classrooms/{id}/gaps` | `[{concept_id, name, mean_mastery, pct_below_50, n_students}]` sorted weakest first |
| GET | `/teacher/classrooms/{id}/misconceptions` | `[{misconception_id, statement, concept_id, n_students}]` sorted by prevalence |
| GET | `/teacher/classrooms/{id}/at-risk` | students with overall mastery below 0.4 or 3+ overdue concepts |
| GET | `/teacher/classrooms/{id}/students/{user_id}` | drill-down: mastery per concept, active misconceptions, recent attempts |

## Slice workflow

The API is built **slice by slice** (concepts, then diagnostic and practice, then AI-assisted answers, then Teach-Back, then teacher analytics), each slice shipping backend and UI together. After every slice the backend exports `openapi.json` and the frontend regenerates its types with `pnpm gen:api`. The OpenAPI shape must match this document; if a slice needs a different shape, update this document first and note it in `docs/DECISIONS.md`.

## Frontend client

`pnpm gen:api` runs `openapi-typescript` against the exported `openapi.json` (or the running backend) and writes to `frontend/src/lib/api/`. A thin typed fetch wrapper adds `X-Demo-User-Id` and maps the error envelope to a typed `ApiError`.
